# 风险与控制

以下说明当前实现的限制与运维责任。功能用法见[文档目录](README.md)，历史测试环境见[归档](history/README.md)。

## 单机与备份

Gitea、对象、图片和任务状态同机保存。磁盘或主机故障可能同时影响源内容和服务，宿主机上的快照不能替代异机备份。项目不默认配置加密异机备份与外部通知；应安排一致性窗口，验证数据库、对象/IAM、密钥和配置的恢复。

## 权限

初始 OC 用户具有管理权限。多人日常使用应创建个人 IAM/Gitea 账号，缩小授权并安排轮换、离职回收。Stargate 只保护入口，不降低应用账号权限。

Publisher 的共享身份和 Deploy Key 覆盖已接入仓库。白名单限制发布来源，但不构成不同信任方之间的隔离；需要租户隔离时使用独立身份、队列或部署。初始化仅用于新环境，已有和中断状态会被拒绝；没有自动修复部分初始化的命令。

## 容量与处理时间

Git 拉取具有目录增长、单仓库/全局缓存、时间和进程地址空间预算；队列具有活动/合计记录与预留字节准入限制。普通发布和恢复采用文件流上传、分块校验。

目录预算是周期检查，可能瞬时超量；进程地址空间限制不等于所有容器的内存总和。Gitea 源端打包、备份、Docker 日志及恢复记录也需要独立容量管理。配置文件系统配额、容器限额和外部告警，按实际增长调整预算，不能依赖看板提示防止整机耗尽。

本地版本、历史对象和审计有各自保留机制，默认保护当前、回滚、固定和在途引用。Git 历史、未知对象、未完成分片及其他 S3 版本不由这些机制自动清理。归档任务仍计入队列合计额度。详见[资源预算](resource-limits.md)、[本地保留](retention.md)、[对象保留](object-retention.md)和[审计归档](restore-audit.md)。

## 发布、接入和恢复

Git、S3、图片 current 与任务记录没有联合事务。任务完成前部分对象可能已公开；图片切换与状态落盘之间存在中断窗口。第二次检查分支头之后仍可能收到新的 Push，因此当前图片不保证始终等于瞬时 Git HEAD。

`repo ensure` 失败时可能保留已创建的仓库、Key、Hook 或权限。先查看失败阶段，再重复同一命令；不要把旧配置整份覆盖回去，撤销其他仓库后续变更。

恢复校验已有内容后重建缺失对象/副本，默认不切换版本。核对和结案保留原报告；结案是当时证据的确认，不是改写历史。外部管理员绕过锁改动对象、目录或状态时，应用锁无法消除竞态。原始报告和收据应纳入备份。

## 删除与历史链接

实际清理不可逆，可能使旧附件链接失效。当前存储验收未观察到 DeleteObject If-Match 的条件保护，执行对象清理须确认应用独占写入；外部同时修改对象时仍可能误删。中断可能留下部分删除版本，应按收据恢复，不将非零退出当作未删除。

固定图片使用短缓存，客户端在有效期内可能看到旧内容。需要绑定内容版本时使用带 SHA 的附件 URL。

## 公开内容

图片只按扩展名限制，不检测文件签名或恶意内容。其他附件可能包含 HTML 等主动内容。对不可信内容应评估独立域名、强制下载、sandbox/CSP 和扫描；不要在公开附件域名放置需要保密的材料。

## 部署与供应链

部分目录、网络、端口、桶前缀与 Traefik resolver 名称固定在配方中，修改一处不会自动迁移全部依赖。改变路径或域名后，应检查认证回调、证书、映射与原有链接。

镜像固定摘要，但 apt 软件包、Python 依赖和 Actions 仍不构成完全可复现的构建。应按需要增加依赖哈希、SBOM、漏洞扫描与升级回归。内部十年证书仍需限制私钥权限、监控到期并在泄漏时轮换。

## 看板与告警

Info 各类数据有独立采样周期，历史恢复记录也可能属于不同 SHA。缓存失败或过期会提示；没有提示不等于实时检查了所有内容。在线审计有读取上限，坏记录和未结案证据可能阻止归档，需要人工处理。

自动恢复仅按作用域、冷却和次数限制重启持续不健康的容器，不修复数据。维护前暂停相关定时器与正在运行的服务。安全报告渠道见[安全说明](../SECURITY.md)。
