# 从 Git 恢复历史对象

## 使用方式

restore-objects 从已配置仓库的指定提交恢复 S3 对象，同步执行并返回校验结果。它使用现有 Publisher 的 Git Deploy Key、S3 身份和内部 CA，不需要清理账号，也不增加删除权限。

```sh
cd /app/open-assets
ASSET_KEY=main-images
# 替换为目标提交的完整 40 位小写 SHA。
ASSET_COMMIT=0123456789abcdef0123456789abcdef01234567
sudo ./scripts/open-assets \
  restore-objects "$ASSET_KEY" "$ASSET_COMMIT"
```

命令会写入缺失对象、修复符合条件的元数据，并更新恢复记录。正常结果包含：

- status=complete：完整对象集合、内容哈希与响应元数据均已复核。
- uploaded_objects：本次补齐且收到成功响应的对象数。
- repaired_objects：内容相同、本次修复元数据且收到成功响应的对象数。
- verified_objects：最终逐对象读取、计算完整哈希并通过校验的数量。
- logical_bytes：原清单中对象大小之和；不是本次网络流量或物理磁盘增量。

重复执行会再次校验，通常 uploaded_objects 和 repaired_objects 为 0。默认不改变 current、published 或回滚历史，不创建发布任务，也不修改原任务、归档和去重记录。仅显式 --with-local --rollback 才执行切换。

## 解决已完成任务的去重问题

普通 publish 仍按仓库、SHA、manual 身份去重。若对应手工任务已经完成或归档，再次 publish 返回旧任务 ID，不能据此认为对象已恢复。

restore-objects 直接执行独立恢复流程，不经过任务入队，因此已完成的 auto/manual 任务和归档不会阻止它运行。不要删除任务或归档、把 published 改为 pending，或改变 Webhook delivery 来绕过去重。普通 retry 仍只接受失败任务。

## 恢复前提

- 仓库仍在白名单中并已启用。目标提交必须存在于固定远端、固定发布分支的当前历史内；命令不接受请求提供的 Git URL、桶名或磁盘路径。分支已重写、提交不可达或远端离线时会停止。
- 对应的 state_root/manifests/<key>/<sha>.json 必须保留且可信。该清单记录原始路径、大小、SHA-256 和 Content-Type。缺少或损坏时应先从可信状态备份恢复；本功能不根据现有存储内容猜测原清单。
- 当前导出规则和容量限制必须仍允许导出该提交。源目录调整导致 Git 内容与原清单不一致时会停止，不会用新规则静默替换旧版本。
- S3 身份需要该前缀的 ListBucket、GetObject、PutObject，Git SSH 密钥和已固定的主机公钥应有效。
- 发布状态、清单和删除收据应保持应用 UID/GID 20010 的正常权限。只读清单不足以完成恢复：成功时需要更新时间、写入报告和恢复标记；从 root 备份还原测试/生产状态后应核对属主与目录访问权限。
- 执行期间避免通过 OC、其他 S3 客户端或并行运维脚本修改目标前缀、清单和删除收据。应用锁保护正常发布、回滚及清理；它无法约束绕过锁的管理员。恢复不依赖服务端条件写入来消除外部并发竞态。

## 校验与写入顺序

1. 非阻塞获取 Worker 锁，读取原清单和删除收据。配置非法、收据身份/范围冲突时停止。
2. 从固定分支 fetch，确认目标为 commit 且属于允许分支历史。直接导出 Git blob，不检出或执行仓库脚本；符号链接、submodule、LFS 和不安全路径仍按发布规则拒绝。
3. 将完整 Git 导出的路径、大小及哈希与原清单比对，校验 staging 文件树。恢复使用原清单的 Content-Type，避免依赖当前系统 MIME 推断结果改写历史响应类型。
4. 列出精确版本前缀，拒绝额外对象和大小冲突；逐一读取所有现存对象并计算完整 SHA-256。整批预检查通过后才开始写入，现有内容冲突不会被覆盖。
5. 写入前再读取目标，补齐缺失内容。内容已经正确但 sha256 元数据、Content-Type 或应用 Cache-Control 不符时，以相同字节修复这些元数据；保留其他自定义 Metadata 键。
6. 重新核对完整对象集合，逐一读取并验证内容、大小和响应元数据。清单未变后，刷新其使用时间，最后把有效删除标记改为 restored。

不删除版本前缀中的额外对象，也不会通过清空前缀来重建。恢复只校验当前可见对象，不改变桶版本控制、不清理非当前版本或删除标记。ACL、标签、对象锁等未记录在发布清单中的属性不在恢复保证内；同字节元数据修复仍是 PutObject，不应把它当作保留所有外部自定义 S3 属性的通用迁移工具。

数据以 1 MiB 块读取并计算哈希，上传使用本地文件流。Git 导出仍沿用单文件读入内存的发布实现，Git fetch 也不受 public 内容容量上限约束。最多接受 10,000 个清单文件、50,000 次 S3 调用，请求起点间隔至少 0.05 秒。连接/读取超时为 5/15 秒，SDK 不自动重试。

总检查预算沿用 WORKER_MAX_JOB_SECONDS，默认 1800 秒，支持 60 至 86400 秒；检查不能中断已开始的 Git、网络或内核 I/O。Git 调用仍受自身超时约束。大版本可能耗尽预算或空间；不要把参数设为无限，也不要反复并行启动。

## 锁、失败与重试

获取不到 Worker 锁时返回 status=busy，退出码为 2；本次没有开始恢复，可等待当前发布或维护结束后重试。正常完成退出码为 0，失败为 1，中断为 130。

恢复期间正常入队可继续；发布循环跳过锁忙的一轮，清理返回 busy，显式图片回滚可能等待 Worker 锁。工作循环在维护锁忙时跳过该轮并继续刷新心跳，避免长恢复被误判为进程失活。健康状态只表示工作循环存活，不能证明待发布任务已经完成；显式 rollback-images 等命令仍可能等待锁。

S3 对象逐个写入，不提供整版事务。第一次 PUT 前先刷盘记录写入意图；强制终止后计数可能不完整，但会保留存在写入可能的标记。失败、中断、超时或响应丢失可能已经恢复部分对象；不会自动删除它们。原删除屏障只有在完整复核成功后才解除。使用同一个 restore-objects 命令重试即可，不依赖失败发布任务 ID；若发现内容冲突，应先调查并从可信备份处理，不要强制覆盖。

最近结果按 key/SHA 保存到 state_root/object-restores/<key>/<sha>.json，包含阶段、计数、时间、范围/清单摘要和错误类型，不保存凭据、Git URL、对象名或 SDK 原始错误。相同版本覆盖最近结果，不保留无限次尝试；不同版本的记录需随状态备份管理。进程被强制结束时可能留下 running，表示尚未结案，并不证明没有写入。成功之后的报告落盘也可能失败，应结合对象核验和删除标记判断，不能只依据退出码推断无影响。

完整恢复会刷新清单的使用时间，给予新的保留窗口，即使本次无需上传也会更新。恢复记录反映当时的复核结果，不持续监测外部对象是否随后被改写。

## 后续图片回滚和看板

默认对象模式不重建本地副本。需要恢复已清理的 public/图片目录时使用下文 --with-local，只有额外指定 --rollback 才显式切换。对象恢复成功不表示图片已回滚。

Info 中对象数量/大小在下一轮完整对象采集后更新；候选规划由下次对象保留预览重新计算。恢复不会伪造或撤销过去的清理结果，也不触发网页端 S3 遍历。需要立即核对保留候选时，手工执行一次只预览命令，见[对象保留](object-retention.md)。

正常结束和可捕获异常会移除本次 .restore- 临时目录；强制结束或掉电可能留下目录和未结案报告。重试会重新导出 Git，不信任并复用遗留临时文件。遗留目录需在确认没有恢复进程及相应维护锁持有者后由运维核对处理，不纳入自动对象清理。

## 重建本地 public / 图片副本

需要同时恢复已被本地保留策略清理的副本时，显式添加 --with-local：

```sh
sudo ./scripts/open-assets \
  restore-objects "$ASSET_KEY" "$ASSET_COMMIT" --with-local
```

此模式仍执行完整 S3 恢复和读回校验，同时从同一份 Git 导出重建：

```text
images/repos/<key>/releases/<sha>/          # 完整 public 内容
images/repos/<key>/releases/images-<sha>/   # public/images 的相对路径投影
```

不从未知缓存或未校验的存储对象拼装本地副本。原清单、源分支历史、导出限制和应用目录权限等前提仍适用。已有副本会重新校验完整文件集合、大小、SHA-256 及普通文件/目录类型；发现损坏、额外文件、软链接或特殊条目时停止，不清空或覆盖它们。只缺少一份时仅安装缺少的那份。

完整 public 暂存与图片暂存均在图片父目录所在文件系统内准备，校验并刷盘后分别重命名到 releases。两份目录的安装不是一个联合原子操作；中断可能留下已完成的一份，重试会校验并保留它，再补齐另一份。当前版本、任务和归档不会因默认恢复而改变。local_full_rebuilt / local_images_rebuilt 表示本次安装了相应副本，local_verified 表示最终两份副本都校验通过；重复执行通常两个 rebuilt 都为 false。

带本地恢复时，图片盘预留检查按仓库 max_bytes 的三倍计算，以保守覆盖 public、图片投影及对象数据同盘时的增量；对象模式保持两倍检查。它不是对其他文件系统或 Git 历史的完整配额，空间不足会停止。

## 完整恢复后显式切换

恢复并在同一次维护锁内重新校验、显式切换到目标版本：

```sh
sudo ./scripts/open-assets \
  restore-objects "$ASSET_KEY" "$ASSET_COMMIT" --with-local --rollback
```

--rollback 必须与 --with-local 一起使用，不能用于其他命令。没有 --rollback 时，即使目标目录已重建也不切换 current 或 published。显式切换前还要求原 current/published 引用一致，S3 对象和两份本地副本均已校验，然后复用图片回滚的切换前/后校验、原子软链接替换和回滚点保护。activated=true 表示显式切换流程完成；已在目标时仍重新校验。

也可先只运行 --with-local，人工检查后另行执行 rollback-images。独立 rollback-images 校验本地副本和对象恢复标记，不重新下载全部对象；希望切换前重新核验 S3 时，应再次使用上面的组合命令。

切换或 published 写入出现可捕获异常时，程序尝试恢复原 current 和 published 内容；回滚保护可能多留版本。文件系统持续故障、掉电或强制结束仍可能留下混合状态，不能宣称跨文件事务：activation_uncertain 表示应核对两个引用，activated=false 不证明没有发生过临时切换。先修复不一致状态再重试，不应绕过检查。

local_partial_possible 表示本地安装可能未完整结案，独立于 S3 的 partial_possible。第一次目录安装和显式切换之前均保存意图。失败可能已经补齐对象或安装部分本地副本，这些有效内容不会被自动删除；恢复标记只有在本次要求的对象及本地校验均完成后才更新。恢复报告字段是最近落盘状态，不是逐文件实时进度。

Info 的[最近恢复结果](info.md#恢复结果与状态核对)按仓库显示对象、本地副本和显式回滚的报告摘要。它只反映最近一次已持久化的尝试及当时的验证状态，不替代私有报告、当前版本核对或持续完整性检查。

恢复未结案或状态不确定时，可先运行 [check-restore](restore-check.md)，重新读取对象、本地副本与 current/published，保留原恢复证据后再决定重试或人工恢复。核对本身不修复、不切换、不解除屏障。

完成诊断并人工复核后，可用 [close-restore](restore-close.md) 显式结案符合条件的未结案或不确定恢复。命令重新核对并单独保留原报告快照和审计记录，不把原失败改写为成功，不切换版本或解除清理屏障。
