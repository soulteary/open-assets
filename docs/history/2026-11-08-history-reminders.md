# 验证范围

本次记录覆盖 Info 历史提醒分类、灰色状态及下一步操作建议。此前诊断看板、CLI 与发布流程的验证见[历史记录](README.md)。

## 隔离验证（2026-11-08）

- 250 项 Python 测试在无网络、只读源码、256 MiB 内存限制的独立 Linux 容器中通过；31 项界面测试、Ruff 与文档链接检查通过。
- 匹配仓库、SHA 和原报告摘要的结案可标记对应提醒已处理，原恢复状态不被改写。不同目标、同一 SHA 的新尝试、较早结案、范围/清单/原报告变化和读取异常不能被旧证据覆盖。
- 仅引用变化或过期的成功核对归为历史记录；失败和原报告不确定不会仅因过期而消失。通过核对不等于替不确定恢复结案。
- 用真实格式的恢复、核对和结案文件验证关联；目标 SHA 和关联摘要仍留在采集器内部，没有增加到公开快照。
- 行颜色、页签与顶部摘要使用同一分类；已处理和历史记录区分文案，保留时间与变化说明。审计容量提醒独立保留。
- 界面提供核对、条件恢复、结案、归档校验和预览建议，不提供执行按钮。健康恢复的历史失败须有较晚重启记录及随后健康采样才标灰。

## 已有服务器验收

- 部署前核对源码并备份应用、Publisher 与 Info 状态。仅重建 Info；其余容器保持原 ID，九个容器健康、九个定时器运行。
- 原始恢复、核对、结案和 published 文件哈希及 current 链接不变；私有配置、凭据和证书不变。没有运行恢复、结案或清理来消除提醒。
- 浏览器确认：成功核对后仅引用变化的记录显示灰色历史记录，状态核对页签取消提示，行内显示对应核对命令与目标参数说明。独立审计事项继续提醒。
- 连续读取 Info API 不修改诊断缓存。既有 doctor、日常 CLI、图片和附件字节/Range、受保护管理入口的匿名跳转和认证读取通过。

分类来自有界、只读采集，不增加 S3 请求或业务检查；页面刷新不进行重新核对。灰色历史记录不证明问题已修复，灰色已处理也不代表内容持续有效。线上不制造故障、不改写报告；异常匹配在隔离测试中验证。公开源码检查排除生产域名、地址、私有材料和运行截图。
