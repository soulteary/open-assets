# 易用性检查与现有缺陷

检查日期：2026-11-08。范围为仓库源码、命令帮助、文档和 Info 界面；用临时配置/故障输入、隔离运行与已有部署验证改进。此记录不是渗透测试、漏洞库扫描、全量灾难恢复或多租户保证。

## 本轮修正

**操作入口分散，仓库身份难找。** 原宿主机脚本只支持接入，发布和恢复要记 Docker 前缀，新增功能分散在多份文档。现在统一日常入口，新增只读 repo list、doctor 和 links。管理接入继续委派原逻辑；入口统一没有改变权限或操作语义。

**帮助与参数校验滞后。** 原单一参数表把所有开关展示在每个命令中，部分 publish/retry/rollback 缺参在读取配置后才报错。现在每命令独立帮助和必填参数，提前拒绝错误 SHA/key/任务 ID、范围和不适用开关；运行异常保留脱敏反馈。status 支持精确 key/SHA 过滤。配置中的 enabled/serve 必须是 YAML 布尔值，避免带引号的 "false" 被当作真值。

**地址需要人工拼接。** 图片前缀、桶/版本路径和中文/空格/+/% 编码容易出错。links 从配置生成地址，明确未验证存在；固定图片 URL 与指定 SHA 附件 URL 的区别仍需保留。

**说明过长，但没有下一步。** Info 原来连续展示实现边界，用户难以快速判断该做什么。现在结论和安全的下一步常显，详细口径放入原生 details 展开；恢复阶段给出中文名称。README 合并重复功能追加段落，新增按任务选择命令的速查。

**tab 隐藏了异常记录。** 增加常显、可点击的详情提示和 tab 提示标记，覆盖旧采样、失败、不确定、待清理与拒绝记录。提示不等于服务故障，不把拒绝操作当作发布失败。URL fragment 可保存选中面板，重新载入也能回到同一 tab。

**未来时间可被误判为新快照。** Info 原读取逻辑把负年龄截为零；现在拒绝超过当前时间五分钟、布尔或负数时间戳，避免错误时间长期显示为刚更新。正常时钟小幅差异仍容忍，失效时显示快照不可用。

## 仍需处理的缺陷

**优先级高：资源和全局容量约束不完整。** 单仓库导出限额在 Git fetch 之后，不能约束 Git 历史或队列总量。普通发布仍把单文件读入内存；恢复已有流式校验。应完善 Git/队列预算、外部容量通知、资源限额与可重复恢复演练。页面告警和 doctor 不能代替这些措施。

**优先级高：权限和单机故障边界。** 初始 OC 账号仍是管理身份，Publisher 共享身份/Deploy Key 覆盖已接入仓库；仓库不是租户边界。数据、源仓库与服务同机，配方不默认建立异机备份和通知。多用户使用前应先做最小权限、密钥轮换、外部告警和恢复验证。

**优先级中：跨系统仍非事务。** 发布、仓库接入、清理及审计各有中间状态；新帮助不能消除强制终止、响应丢失和外部并发写入。结案是对当时证据的人工确认，不是把旧失败改成成功，也不证明历史切换。

**优先级中：诊断与入口仍有边界。** doctor 只检查配置、应用容器、timer 启用和主机快照；不验证外部 Traefik、DNS、公网证书链、业务字节、每个低频缓存或 timer 最后执行成功。详细失败原因仍需私有报告，当前没有全流程关联 ID 或逐项校验错误码。保留清理、统计采样、备份和证书工具尚未全部纳入入口；它们的权限不同，不能简单把删除操作转给 Publisher。

**优先级中：Info 不是历史查询工具。** 各面板取最近记录，可能不是同一提交。为保持现有最小披露，网页仍不展示完整 SHA/审计 ID；按提交调查使用 CLI。数据有不同采样周期，不能把主机快照刷新当作所有数据刷新。只读页面不提供修复按钮。

**优先级中：规模与拓扑上限。** 在线审计保留 512 项读取上限；未结案/坏记录不能强制归档，极端增长仍会超限。查询/归档也有目录项及时间预算，未引入索引数据库。路径、网络、端口和部分公开路由仍有固定值；例如默认附件路由匹配 attachments 前缀，修改 bucket 并不自动迁移所有路由。links 不能验证这种定制部署正确。

**优先级中：公开内容与供应链。** 非图片附件可包含主动内容，当前没有统一强制下载/sandbox 策略或恶意内容扫描。固定镜像摘要之外，系统包与 Python/Actions 构建约束仍不构成完整可复现/漏洞保证。应独立评估内容信任、依赖锁定与扫描，不能通过界面说明宣称已经解决。

建议顺序是先补资源预算、外部告警及异机恢复，随后收紧日常权限，再针对实际规模完善索引、关联诊断和部署前拓扑检查。现有技术风险与控制详见 [risks.md](risks.md)，使用方法见[操作速查](operator.md)。
