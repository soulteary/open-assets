# 使用限制

日常命令见[操作速查](operator.md)，具体技术风险见[风险与控制](risks.md)。以下限制会影响操作方式。

## 部署与初始化

配方使用固定目录、网络和端口，面向一台 Linux 服务器。节点名不会隔离同机多套部署。首次准备和初始化会拒绝已有状态；中断后保留现场，不能靠重跑初始化修复。后续接入仓库使用 `repo ensure`。

## 发布与诊断

Git 和队列已有资源预算，发布采用流式上传和分块校验。目录预算是周期检查，仍需容器限制、文件系统配额、外部告警和异机备份。

失败任务要明确重试。部分错误仅返回固定异常类型，仍需结合阶段、私有报告和服务日志定位。`doctor` 区分必需和可选定时器，检查 service 最近执行结果、快照与各统计缓存的采样年龄；不验证所有业务文件，也不自动修复，详见[部署诊断](doctor.md)。

## 看板与恢复

Info 展示各自最近的采样或报告，面板之间可能不是同一提交。调查指定版本使用 CLI；历史失败记录可能继续显示提示，需结合核对及结案记录判断是否仍待处理。

恢复、核对、结案和审计是不同操作。核对通过不会切换版本或自动结案；结案保留原证据。清理默认预览，实际删除可能使历史附件链接失效。

## 权限与维护

初始 OC 用户是管理身份，日常多人使用应建立各自账号。Publisher 共享授权覆盖已接入仓库，白名单不构成多租户隔离。备份、内部证书更新和统计强制采样仍使用各自的宿主机工具；对象删除使用独立身份。
