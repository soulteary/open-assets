# 恢复状态核对

`check-restore` 对指定仓库和完整 commit SHA 重新检查对象、本地 public/图片副本和 current/published。它适用于恢复报告停在 running、切换状态不确定、恢复命令返回失败，或需要确认历史版本现状的场景。

```sh
cd /app/open-assets
sudo docker compose exec -T publisher python -m open_assets \
  check-restore "$ASSET_KEY" "$ASSET_COMMIT"
```

命令同步执行，默认不修复、不切换版本，没有 `--rollback` 或 `--apply` 选项。唯一持久化输出是独立的核对报告及维护锁文件；不改写对象、目录内容、current、published、原恢复报告、清理屏障、任务或回滚保护，不刷新清单和版本目录的保留时间。读取本身可能更新文件系统 atime。日志及命令输出仍应作为私有运行材料管理。

## 核对范围

基准是已有、可信的原发布清单，不从远端 Git 拉取或导出，也不以恢复报告里的成功计数代替数据核验。仓库必须已启用，清单身份、路径、大小、SHA-256 和 MIME 均需合法。清单缺失、损坏或不可信时，先从可信备份恢复证据，再执行核对。

1. 对象：精确列举该 key/SHA 前缀，拒绝缺失、额外对象或大小不符；逐对象下载并验证长度、SHA-256、MIME、Cache-Control 和 sha256 元数据。不会上传、删除或修复元数据。
2. public：验证完整本地快照的文件集合、大小及 SHA-256，拒绝链接、特殊条目和额外文件。
3. 图片：独立验证图片投影副本，不从 public 的成功推断图片副本正确。无论原恢复是否请求本地重建，两份副本都会核对；对象模式恢复之后本地副本仍缺失，是一个有效的问题结果。
4. 引用：验证 current 软链接格式和目标目录，以及 published 与该 current 对应清单的完整内容一致。另报告 current/published 是否指向本次核对的 SHA。两者同时不存在表示尚未发布；一致地指向其他版本不是错误。这里不校验其他当前版本的全部文件和对象，内容校验范围始终是命令指定的 SHA。
5. 清理屏障：原对象清理记录仍为 deleting 或 complete 时报告 blocked，即使所有对象已齐全也不解除屏障。restored 或没有屏障不阻止本次核对；坏记录则报告失败。

每一项独立记录，某项失败后尽量继续检查其他项；全局前提失败或时间预算用完则不能宣称完成全部核对。整个操作持有与发布、恢复、清理相同的 Worker 锁，锁忙时立即返回，不长时间阻塞 Worker 心跳。请求数、速率和 `WORKER_MAX_JOB_SECONDS` 预算复用恢复 CLI；大版本会占用读取带宽和维护锁，建议按需执行，不安排高频自动运行。

## 结果和退出码

标准输出为 JSON。需要区分执行状态与诊断结论：

- `status=complete` 表示本次检查流程走完，不代表所有检查通过；`diagnosis=verified` 才表示五项均通过且原报告可读取或不存在。
- `diagnosis=issues` 表示发现缺失、冲突、屏障或证据问题。`checks` 中每项给出 ok、blocked、failed 或 unavailable，以及有限原因代码。
- `status=failed` / `diagnosis=unresolved` 表示前提不成立、命令中断或未能完整核对；持久化 running 也可能是进程被强制结束后未结案。
- `source_status` 和 `source_uncertain` 保留原恢复报告的状态。核对通过不会把原恢复 running 改为 complete，也不撤销原来的不确定提示。`current_is_target` / `published_is_target` 仅说明核对当时的引用，不能证明过去的切换成功或从未发生临时切换。

退出码：0 为 verified；1 为发现问题、未完整核对或命令失败；2 为锁忙，或参数用法错误。参数错误由 argparse 输出，锁忙输出 JSON。自动化应先检查退出码，再解析成功返回的报告；不能只看到 complete 就判断正常。

报告位于 `state_root/restore-checks/<key>/<sha>.json`。同一目标覆盖最近核对；不同 SHA 分开记录。报告包含时间、范围/清单/原报告/引用摘要、计数和有限原因，不记录对象名、Git URL、凭据或 SDK 原始错误。首次检查前及每个阶段前持久化进度；强制结束或报告最终写入失败时可能仍显示 running。核对不提供跨 S3 与文件系统的快照事务；外部管理员不能在期间绕过应用锁修改目标。

## 根据诊断处理

先核对每项结果和实际 current/published，保留私有报告。对象或本地副本缺失时，可以使用 [restore-objects --with-local](object-restore.md#重建本地-public--图片副本) 重建并校验；该命令默认不切换。已有内容冲突时应调查来源，不能用核对命令强制覆盖。清理屏障仍在时，使用正常恢复流程完整验证后解除，核对本身不会解除。

需要显式切换时，另行使用已有的恢复/回滚命令。current/published 不一致时先从可信状态核对恢复，不能把修改其中一个文件当成通用修复。核对通过后也应依据原操作意图决定后续动作；CLI 不会自动结案、不重放任务、不推断应选择哪个版本。

## Info 展示

[Info](info.md#恢复状态核对)只读展示每仓库最近启动的一次核对。它与“最近恢复结果”是两组记录，目标 SHA 可能不同。采集过程不自动重新下载对象，不把核对结果写回原恢复结果。

对象检查针对当前可见的对象集合，不枚举 S3 历史版本或未完成的分片；也不证明对象此前从未变化。缺失的本地副本会报告问题，即使该版本原本只计划恢复对象，也不会据此自动重建它。

核对通过后若需要显式结案，可使用 [close-restore](restore-close.md)。结案会在同一锁内再次完整核对，不直接采纳本次缓存结果；原恢复报告保留，另写结案和审计记录，不自动切换或解除屏障。
