# 人工确认结案拒绝提醒

`acknowledge-closure` 用于已经人工核实无需处理的**结案拒绝提醒**。它只记录对指定拒绝的确认，不把恢复标为结案，不修复对象或文件，不切换版本，也不解除清理屏障。原拒绝、原恢复和既有审计文件保持原样。

此命令仅在部署服务器宿主机使用，需要 root 和已初始化的部署。确认对象必须是指定仓库最近的一次在线 `refused` 结案记录；成功、失败、运行中、旧记录或已归档记录不接受确认。其他恢复或核对问题不会因此消除。

## 找到这次拒绝

```sh
cd /app/open-assets
sudo ./scripts/open-assets restore-audit-list "$ASSET_KEY"
```

按目标 SHA、时间和拒绝原因找到 `audit_id`，将完整的 32 位小写 ID 保存为 `CLOSURE_AUDIT_ID`。它不是 commit SHA、任务 ID 或人工确认 ID。查清实际原因后，将说明保存为 `ACK_REASON`，不要直接照抄示例或填写凭据。

例如，拒绝由一次未执行恢复的验收目标产生，已经核对原始审计、目标和实际数据，确实无需恢复结案，可以记录这一事实。若原报告是意外缺失、数据仍有问题，或无法确认发生过什么，应先调查报告与备份，不能用人工确认代替修复。

## 默认预览，再显式确认

```sh
sudo ./scripts/open-assets acknowledge-closure \
  "$ASSET_KEY" "$CLOSURE_AUDIT_ID" --reason "$ACK_REASON"
```

默认返回 `status: preview` 和 `evidence_token`，不创建确认文件。核实对象和当前证据后，将本次令牌保存为 `EVIDENCE_TOKEN`，再次执行：

```sh
sudo ./scripts/open-assets acknowledge-closure \
  "$ASSET_KEY" "$CLOSURE_AUDIT_ID" --reason "$ACK_REASON" \
  --confirm "$EVIDENCE_TOKEN"
```

原因必填，去掉首尾空白后为 1–256 字符，不能包含控制字符。原因保存在私有确认审计中，不进入 Info 快照，命令返回值也不回显原因。SSH 终端历史仍由运维人员管理。

令牌绑定预览时观察到的证据。预览后证据变化，确认返回 `refused / evidence-changed`；需要重新核实、重新预览，不能直接复用旧令牌。令牌不是登录凭据，不替代宿主机权限。

成功返回 `acknowledged` 和独立 `ack_id`。相同证据、相同原因重复执行复用已生效的确认，`reused: true`；不同原因会保留一条新审计，不改写旧原因。

退出码：预览或确认成功为 0；拒绝、文件不可读、证据损坏或未能完成为 1；Worker 锁忙或参数错误为 2。不要只看到命令结束就认定已确认，应检查状态和退出码。

## 证据变化后的行为

确认绑定仓库与拒绝 ID、原 intent/result 及已有证据快照、当前配置、目标恢复/核对报告、清单、current/published，以及该仓库最近恢复、核对和结案的身份。缺失文件被明确记录为缺失；无权限、损坏或无法比较不视为缺失。

新尝试、报告或清单变化、引用切换、配置变化都会使旧确认失效。配置绑定使用整份仓库配置摘要，因此新增其他仓库也可能要求重新核实。程序不会因为旧确认存在而自动确认新的拒绝。

这些是文件和程序状态的证据，不是持续的对象内容校验；外部 S3 修改而未改变本地证据时，不保证能由本功能发现。对象完整性需要另行运行 `check-restore`。写入使用 Worker 锁，并在发布确认指针前重新观察一次，但不提供跨文件、外部管理员和对象存储的联合事务。

## 私有审计与中断恢复

文件位于 `${DATA_ROOT}/closure-acknowledgments/<key>/`：

```text
latest.json
<ack-id>/
├── ack.json
├── intent.json
├── result.json
└── source.json / check.json（原审计中存在时）
```

该目录位于 Publisher 的 `/state` 挂载之外，宿主机 root 持有，不能由发布进程直接写入。父目录所有权不符或可被组/其他用户写入时拒绝确认。现有 backup.sh 与 snapshot.sh 备份整个 DATA_ROOT，已覆盖此目录。

每次确认使用新目录，原始拒绝及其快照按原字节保存；`ack.json` 保存原因、时间、执行 UID 和证据摘要。UID 是进程身份，不代表独立的人类账号认证。记录和快照独占写入并同步到磁盘，校验后才原子发布 `latest.json`。

记录中的 `status: recorded` 表示已保存人工审核证据；只有指针引用的记录完整且仍匹配当前证据，提醒才生效。中断可能留下未被指针引用的目录，这不是有效确认。原样保留用于调查，修复原因后重试；不要删除记录或手工改写指针来让页面变灰。若指针发布后调用方丢失响应，可重复相同命令查询是否复用。

完整性校验用于发现损坏和证据不匹配，不是签名或防宿主机管理员篡改的存储。重要审计应随备份保存到独立、受访问控制的位置。

每仓库最多保存 1000 个确认目录。达到上限、存在异常目录、链接或损坏的当前确认时拒绝继续写入，不自动删除历史。该上限不是磁盘配额；需要继续使用时先备份并制定独立维护方案，不通过移走原拒绝来绕过保护。现有 `restore-audit-archive` 不归档这些确认目录，整个 DATA_ROOT 的备份应包含它们。

## Info 展示

Info 将有效人工确认标为灰色“已人工确认无需处理（非恢复结案）”，展示确认时间，保留原拒绝状态和原因代码。私有原因、目标身份及关联摘要不额外公开。

确认失效时恢复提醒，并提示新尝试或证据变化；记录或证据不可读时不按已处理判断。独立的恢复不确定状态、核对失败及审计容量告警保持原有判定。网页没有确认按钮。

Info 主机采集读取固定指针和有大小限制的文件，不遍历确认历史；页面刷新不检查证据。执行命令后可等待下一次主机采集，或显式刷新：

```sh
sudo systemctl start open-assets-info.service
```
